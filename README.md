# 歌单文件桥接 · Twilight Echo 插件

把任意播放器导出的歌单文件**导入成 Twilight Echo 的本地歌单**：
m3u8、m3u、pls、xspf、wpl、asx、fpl、fplite。几十个歌单不用在播放器里重新整理一遍。

> 这个插件不提供音源、不播放音频。它只做一件事：把歌单文件变成「音乐库 → 歌单」里的本地歌单。

## 配置在哪

**设置 → 系统与关于 → 插件设置 → 歌单文件桥接**

设置页顶部的搜索框输入「插件」可以直接跳过去。展开分组后还要点一下「打开设置」，表单才会出现。

---

## 版本要求

需要 **Twilight Echo 1.3.2 或更高**（任何包含 `twilight.library` 与 `button` 设置字段的版本）。

在 **1.3.1 及更早**上：插件能装、能保存配置，但设置里**不会出现「立即导入为本地歌单」按钮**
——宿主会静默丢弃它不认识的控件类型。这是宿主侧的限制，不是插件的问题。

## 安装

1. 在 [Releases](https://github.com/IRIS-SCI/twilight-playlist-bridge/releases) 下载最新的 `.tep`
2. 扩展中心 →「已安装」→「从本地安装包 (.tep)」
3. 确认权限并启用

启用后立即生效，不用重启，并会弹出一条提示告诉你去哪里配置。

## 配置

**「歌单文件夹」** 是唯一必填项，多个目录用**分号**分隔。支持 `%APPDATA%` 这类环境变量和开头的 `~`。

| 选项 | 说明 |
| --- | --- |
| 歌单文件夹 | 放歌单文件的目录。foobar2000 2.x 用户填 `%APPDATA%\foobar2000-v2\playlists-v2.0`，不用导出 |
| 包含子文件夹 | 递归扫描 |
| 扫描的扩展名 | 默认 `m3u8; m3u; pls; xspf; wpl; asx; wax; fpl; fplite` |
| 文本编码 | 默认自动检测。歌名乱码时改成 `GBK / GB18030` |
| 拆分「艺术家 - 标题」 | 把 `Artist - Title` 拆成两个字段；也控制从文件名提取标题 |
| 隐藏文件已丢失的曲目 | 默认开 |
| 路径修复目录 | 歌单里的盘符变了时，用这些目录重新拼接路径 |
| 立即导入为本地歌单 | 按钮，见下 |

保存后提示行会显示 **「已索引 N 个歌单文件」**。

> 这是一个**单行输入框**，多个目录只能分号分隔，不能换行。

## 使用

在插件设置里点 **「立即导入为本地歌单」** 按钮。按一次 = 扫描一次 + 批量导入一次，
歌单会出现在 **「音乐库 → 歌单」**。

- 会先用表单里当前填的内容，改了歌单目录可以直接点，**不用先保存**
- 可重复执行，按曲目去重，已有的不会重复添加
- 曲目按**文件路径**匹配本地音乐库，和播放器自带的 m3u8 导入是同一套逻辑
- 在后台执行，结果用一条提示告诉你导入了多少首、多少首不在音乐库里

导入出来的歌单是**带完整标签的本地歌单**——曲名、艺术家、专辑、时长都来自音乐库里的歌曲文件。

## 支持的格式

| 格式 | 常见来源 |
| --- | --- |
| `.m3u8` | foobar2000、VLC、MusicBee、AIMP、PotPlayer |
| `.m3u` | 同上，但编码通常是系统 ANSI（中文 Windows 上是 GBK，已自动识别） |
| `.pls` | Shoutcast / Icecast、Winamp |
| `.xspf` | VLC 原生格式 |
| `.wpl` | Windows Media Player |
| `.asx` / `.wax` | Windows Media 元文件 |
| `.fpl` | foobar2000 二进制歌单 |
| `.fplite` | foobar2000 2.x 歌单 |

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 点导入，提示"没有可导入的曲目" | 歌单里引用的文件不在音乐库里。先把音乐文件夹加进音乐库 |
| 导入了但只有一部分歌 | 提示会写有多少首没匹配上；同样是因为文件不在音乐库或路径变了 |
| 加了歌单文件，点导入没反应 | 需要**点一次按钮**才会重扫；插件不会盯着目录 |
| 歌名乱码 | 文本编码改成 `GBK / GB18030` |
| 歌单名是 `playlist-7F9B1053-…` | 只发生在 `.fplite`，同目录的 `index.txt` 没读到 |
| 删了歌单文件，本地歌单还在 | 导入是**单向拷贝**，不会反向删除，要删得手动删 |
| 重命名歌单文件 | 下次导入会按新名字**再建一个**歌单，旧的还在 |
| 曲目名是文件名 | 歌单本身没存标题（`.fplite`、`.wpl` 或只有裸路径的 `.m3u`），从文件名推的 |

其他限制：单次最多 1000 个歌单、20 万条曲目、每个歌单 20000 条、单个文件 8 MiB；
歌单名超过 80 字符会被截断。不支持 `.cue`（foobar2000 自己也导不出 cue，
cue 由播放器自己的音乐库扫描处理）。

## 原理（简述）

- 扫描你指定的目录，按扩展名找歌单文件，解析成**绝对文件路径列表**。
- 把路径连同歌单名交给播放器自己的导入逻辑，由它匹配本地音乐库并写入歌单——
  所以匹配规则、去重、持久化都和自带导入完全一致，插件不碰任何数据文件。
- `.m3u` 大多不是 UTF-8，解码顺序是 BOM → XML 声明 → 严格 UTF-8 → GB18030，所以中文不乱码。
- `.fpl` 是 foobar2000 的二进制格式、没有公开规范，按其逆向结构解析，失败时退回扫描路径字符串。
- 零依赖，只用 Node 内置模块；只读文件，不发起网络请求。

## 权限

| 权限 | 用途 |
| --- | --- |
| `filesystem:read` | 读你指定目录下的歌单文件，并检查引用的音频是否存在 |
| `settings` | 保存上面的配置 |
| `library:write` | 「立即导入为本地歌单」按钮 |
| `ui:inject` | 注册设置面板 |

插件**不联网**，**不写任何应用文件**。
